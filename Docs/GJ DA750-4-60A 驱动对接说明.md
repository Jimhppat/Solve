# GJ DA750-4-60A 驱动对接说明

| 项 | 内容 |
|---|---|
| 设备 | GJ DA750-4-60A 回馈式电子负载，4 通道，单通道 60 V / 60 A / 750 W |
| 驱动包 | `gj.drivers` 0.1.0（源码 `Devicelibrary/GJ/GJ.Drivers`，测试 `Devicelibrary/GJ/GJ.Drivers.Tests`） |
| 驱动标识 | `gj.da750-4-60a`（一经发布不得改名） |
| 分类 / 通道 | `PowerAndLoad` / 通道组 `load`（负载）× 4，功能 `Load`；数量取型号定义 `Da750Model.Channels`，界面编号 CH1–CH4 = 协议第 1–4 槽（与面板丝印的对应见 8 节第 10 项） |
| 链路 | RS-485，9600 bit/s，8N1（旧上位机默认 `9600,N,8,1`） |
| 地址 | 1–127，设备拨码设定；一条总线可挂多台 |
| 依赖 | 主程序 SDK ≥ 1.3（使用命令参数声明与安全状态 `ISafeStateProvider`） |
| 对接规范 | 遵循 `Docs/电源与电子负载模块对接规范.md` 第 4 节电子负载的标准 Key |

## 1. 协议依据

没有厂家手册。协议从旧上位机公共库还原（路径 `GJ.DEV/`）：

| 文件 | 用到的内容 |
|---|---|
| `Load/DA750_4_60A.cs` | 本型号实际使用的 CID（0F、41）、数据区布局、倍率、额定值 |
| `Load/FLoad.cs` | 帧编码 `CalDataFromERS272Cmd`、校验和 `CalCheckSum`、应答码 `checkErrorCode` |
| `LED/CDA_750_4.cs` | 同系列固件的字段注释：8 槽结构、CID 40/41 的区别、模式附加参数含义、状态位定义 |

## 2. 帧格式（ERS272）

```
请求：EE  ADR  CID  LEN  INFO[n]  CHK_H  CHK_L  EF
应答：EE  ADR  RTN  LEN  INFO[n]  CHK_H  CHK_L  EF
LEN = 3 + n，整帧 n + 7 字节
CHK = (ADR + CID/RTN + LEN + INFO 各字节) mod 0x10000，高字节在前
```

- **字节替代**：INFO 与 CHK 中等于 `EE` / `EF` 的字节一律改为 `ED`，接收方不还原（有损）。所以帧内只有首尾是 `EE` / `EF`，驱动以第一个 `EF` 作为帧尾。
- **应答码 RTN**：`F0` 正常；`F1` 校验和错、`F2` 长度错（按暂时性错误重试）；`F3` CID 无效、`F4` 数据无效（按配置错误，不重试）。
- **示例**：读地址 1 的测量值 `EE 01 0F 03 00 13 EF`。

## 3. 命令（CID）

| CID | 用途 | 本驱动 |
|---|---|---|
| `0F` | 读测量值（65 字节） | 轮询使用 |
| `41` | 写全部 8 槽设定，不保存 EEPROM | 带载 / 卸载使用 |
| `40` | 写全部 8 槽设定并保存 EEPROM | 不使用（EEPROM 擦写寿命） |
| `06` | 读设定（48 字节） | 不使用：仅 LED 机型代码用过，本型号未验证 |
| `11` / `12` | 单通道设定（保存 / 不保存） | 不使用：本型号旧驱动未使用 |
| `01` / `08` / `09` | 设地址 / 读地址 / 读版本 | 不使用 |

## 4. 读测量值（CID 0F）数据区：65 字节

固件按 8 槽组织，本型号只解析前 4 槽；最后 1 字节是逆变器状态。多字节字段大端。

| 偏移（每槽 8 字节） | 字段 | 类型 | 换算 |
|---|---|---|---|
| 0–1 | 电压 | int16 | ÷ 20 → V（0.05 V / LSB） |
| 2–3 | 电流 | int16 | ÷ 100 → A（0.01 A / LSB，**60 A 机型专用**；5 A LED 机型为 ÷ 1000） |
| 4–5 | LLC 输入电压 | int16 | ÷ 20 → V，本驱动不上报 |
| 6–7 | 通道状态字 | uint16 | 见下表 |

通道状态字：

| 位 | 含义 | 驱动处理 |
|---|---|---|
| 0 | DC-DC 开启（正在带载） | 点位 `input` |
| 1 | LLC 过压 | 报警 |
| 2–3 | 输入电压：0 欠压 / 1 正常 / 2 过压 / 3 未定义 | 过压、未定义报警；欠压按参数 `undervoltage-is-fault` |
| 4 | 超功率 | 报警 |
| 5 | 过温 | 报警 |
| 6–7 | 直流母线：0 欠压 / 1 正常 / 2 过压 / 3 未定义 | 同输入电压 |
| 8 | 过流 OCP1 | 报警 |
| 9 | 过流 OCP2 | 报警 |
| 10 | LLC 已启动 | 仅在原始状态字中可见 |

逆变器状态（第 65 字节）：Bit 0 过温、Bit 1 AD 采样故障、Bit 2–3 电网电压（同上）、Bit 4 风扇故障、Bit 5 超时故障、Bit 6–7 直流母线（同上）。除欠压按参数外，任何一项都报警。

报警时整次轮询返回 `Device`，原因如"通道 2：过温保护、过流保护（OCP1）（状态字 0x0164）"。读数超出额定值 -5% ~ +120%（电压 -3 ~ 72 V、电流 -3 ~ 72 A）按数据损坏处理，不上报。

## 5. 写设定（CID 41）数据区：48 字节

8 槽 × 6 字节，**4 路设定重复一次填满 8 槽**（与旧驱动 `INFO += INFO` 一致）。

| 偏移（每槽 6 字节） | 字段 | 换算 |
|---|---|---|
| 0 | 模式 | 0 CC 慢速、1 CV、4 CC 快速 |
| 1–2 | Von | 电压 × 20（uint16） |
| 3–4 | 负载值 | CC：电流 × 100；CV：电压 × 20（uint16） |
| 5 | 模式附加参数 | CC：启动延迟 × 10（0–20 s）；CV：0 |

卸载 = CC 慢速、0 A、附加参数 0。协议另有 CP(2)、CR(3)、LED(5)、MTK PE(6)，旧代码对本型号的倍率自相矛盾（CP × 100 时 750 W 超出 16 位），本驱动不提供。

## 6. 驱动对外声明

点位（通道级）：`voltage` 电压 V、`current` 电流 A、`power` 功率 W（电压 × 电流）、`input` 带载状态、`status-word` 通道状态字；模块级：`inverter-status` 逆变器状态。

| 命令 | 名称 | 安全等级 | 参数 |
|---|---|---|---|
| `load.cc` | 恒流带载 | 输出动作 | `current` 电流 0.1–60 A（必填）；`start-delay` 启动延迟 0–20 s（默认 0） |
| `load.cc-fast` | 恒流带载（快速） | 输出动作 | 同上 |
| `load.cv` | 恒压带载 | 输出动作 | `voltage` 电压 5–60 V（必填） |
| `load.off` | 卸载 | 输出动作 | 无 |

| 模块参数 | 默认 | 说明 |
|---|---|---|
| `von` 拉载电压 Von | 8 V（0.5–60） | 4 路共用；旧上位机设定模板的值 |
| `strict-frame-check` 核对长度与校验和 | 是 | 旧驱动注释掉了这两项检查，实机若一直失败再关闭 |
| `undervoltage-is-fault` 欠压状态报警 | 是 | 空闲时若设备本就报欠压，确认后关闭 |

**设定镜像**：协议只能一次写 4 路。会话保存设备已确认的各路设定，命令只改目标通道；会话新建时（启动、改了模块或总线配置）镜像为全部卸载，第一条命令会把其他通道一并卸载。写入超时或被拒不更新镜像。

**安全状态**（SDK 1.3 `ISafeStateProvider`）：总线安全跳闸 / 系统急停时，内核在关闭通道前下发 CID 41，8 槽都写卸载（CC 慢速、Von 照旧、0 A、附加 0）。地址 1、Von 8 V 时整帧为 `EE 01 41 33` + 8 × `00 00 A0 00 00 00` + `05 75 EF`。镜像在下发时就改成全部卸载，不等应答：下发失败时，复位后的下一条命令也不会把跳闸前的拉载写回设备。操作员按位置执行单路安全停止时（`BeginSafeState("load", n)`），只把第 n 路写卸载，其余各路按镜像重发，镜像中第 n 路同样先行改为卸载。

## 7. 相对旧驱动的修正

| 旧驱动 | 问题 | 新驱动 |
|---|---|---|
| CC / MTK 范围检查 `Vin0 > Max && Vin0 < Min` | 永远不成立，越界值照样下发 | 按声明范围检查，越界不发送任何字节 |
| CV 检查 `Vin0 < Max && Vin0 > Min && …` | 条件写反，会拒绝合法值 | 5–60 V 范围检查 |
| LED 检查 | 同样写反 | 不提供 LED 模式 |
| "LLC 开启"读 `Current_Status` | 读错了位（应为 Bit 10） | 原始状态字原样上报 |
| 两位字段"过压"与 `0x10` 比较 | 永远不成立（应为 2） | 按值 2 判断并报警 |
| `checkErrorCode` 注释掉校验和 | 错乱的数据也会被解析 | 默认核对，可用参数关闭 |
| `er = ex.StackTrace` | 丢失错误信息 | 可预期的问题都返回带原因的 `Failed`，不抛异常 |
| 驱动内重试 3 次、同步阻塞收发 | 违反"驱动不做 I/O" | 收发、超时、重试交给内核 |
| CP 倍率 × 100 | 750 W 时超出 16 位，`Convert.ToInt16` 抛异常 | 不提供 CP |
| 保护位只写进文字列表 | 上层无法据此报警 | 保护返回 `Device`，由内核报警 |

## 8. 实机待确认项

| # | 待确认 | 当前做法 | 确认方法 |
|---|---|---|---|
| 1 | 应答的 LEN 与校验和是否符合 2 节公式（旧驱动注释掉了检查） | 默认核对 | 读测量值：模块上线即符合；一直"未成帧"时抓报文核对，必要时关闭 `strict-frame-check` |
| 2 | 应答 ADR 是否等于设备地址 | 不等即判无效 | 同上 |
| 3 | 空闲（不带载、无输入）时输入电压 / 母线字段是否为欠压 | 默认报警 | 上电空闲读一次，看 `status-word` |
| 4 | CC 的附加参数是否为启动延迟（s × 10） | 默认 0 | 设 2 s 延迟，观察带载滞后 |
| 5 | CV 附加参数在本型号的含义（旧代码直接下发原值，LED 机型注释"需为 0"） | 发 0 | 小电流 CV 测试，观察是否限流 |
| 6 | 第 5–8 槽重复第 1–4 槽是否必要 / 无副作用 | 照旧重复 | 看设备读回的第 5–8 槽 |
| 7 | 设备掉电重启后的设定（41 不存 EEPROM，重启回到 EEPROM 中的设定） | 不写 EEPROM | 调试时用 40 写一次"全部卸载"，再断电重启确认不带载 |
| 8 | 逆变器"超时故障"是否为通信看门狗（停止通信后是否自动卸载） | 只报警 | 带载时断开 RS-485，观察是否卸载 |
| 9 | 2.38 A 等低字节为 `EE` / `EF` 的设定值被替代为 `ED` 后的实际电流 | 按协议替代 | 设 2.38 A，读回应约 2.37 A |
| 10 | 协议第 n 槽是否就是面板丝印的第 n 路（界面 CHn） | 按第 n 槽 = CHn | 只给面板 CH1 接被测电源，对 CH1 恒流 0.5 A，确认面板 CH1 带载、读数出现在 CH1、其他各路为 0；CH2–CH4 逐一同样核对 |

## 9. 台架验证步骤

依次进行，前一步通过才进入下一步：

1. **仿真**：总线用仿真模式，挂 `gj.da750-4-60a`，模块上线；恒流带载后读数为 12 V / 设定电流，卸载后归零。
2. **只读**：实机模式连接设备，只轮询不下发命令。核对 4 路电压、`status-word`、`inverter-status`，处理待确认项 1–3。
3. **单路小电流**：被测电源输出 12 V、限流 2 A；Von 8 V；通道 1 恒流 0.5 A。核对电流读数、`input` = 1，其余 3 路保持 0 A。
4. **卸载与镜像**：通道 1 带载时对通道 2 下发恒流 0.5 A，确认通道 1 仍在带载；对通道 1 卸载，确认通道 2 不受影响。
5. **保护**：被测电源电压高于 60 V 或超功率条件下确认模块报警（只在有保护措施的台架上进行）。
5a. **急停卸载**：2 路各带载 0.5 A 时按工作台紧急跳闸，确认 4 路电流在约 1 s 内归零、日志有"已下发安全状态"；拔掉 RS-485 后再急停，确认日志记 Critical"下发安全状态失败"且总线仍锁存 SafeStop。
6. **掉电与断线**：处理待确认项 7、8。
