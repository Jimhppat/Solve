# 电源与电子负载模块对接规范（SDK 1.2）

`Devicelibrary/README.md`（驱动开发规范）规定**怎么写一个驱动**；本文规定**电源 / 电子负载这一类驱动对外必须长什么样**：通道组、点位、命令、命令参数、模块参数用统一的 Key 与语义。

统一之后，设备拓扑接线、数字孪生和测试流程只认本文的标准 Key：同一个老化流程换一家电子负载、换一个型号都不需要修改，只需要换驱动。

- 适用：分类为 `PowerAndLoad` 的全部驱动
- 参考实现：电源 `Devicelibrary/Chroma`（Chroma 62000B），电子负载 `Devicelibrary/GJ`（GJ DA750-4-60A）
- 本文与 SDK 源码不一致时以 SDK 为准，并请修正本文

---

## 1. 电源与电子负载的差别

两者都在"电源 / 电子负载"分类下，但对接方式有本质差别，不能套用同一个模板：

| 方面 | 程控电源 | 电子负载 |
|---|---|---|
| 能量方向 | 向被测产品供电（源） | 从被测产品吸收电流（汇）；回馈型把能量送回电网 |
| 通道功能 | `ChannelFunction.PowerSupply`，组 Key `output` | `ChannelFunction.Load`，组 Key `load` |
| 通道数 | 以单路为主 | 以多路为主（4 / 8 / 16 / 32 / 64 路） |
| 核心命令 | 打开 / 关闭输出，**不带参数** | 按模式带载，**必须带设定值参数**（电流、电压……）；卸载 |
| 设定与输出 | 设定值与输出开关分离，改设定不一定立即生效 | 写入设定即按新值拉载，**设定本身就是输出动作** |
| 安全方向 | 关闭输出 | 卸载（0 A） |
| 协议写入粒度 | 通常单路写 | 常见"一帧写全部通道"，驱动必须维护设定镜像（见 4.4） |
| 设备保护 | 过压、过流、过温 | 超功率、过流、过温、输入过欠压；回馈型另有逆变器、电网、风扇故障 |
| 读数含义 | 输出端电压 / 电流 | 负载输入端电压 / 电流（被测产品的输出） |

由此得出电子负载对 SDK 的两个新要求，已在 SDK 1.2 / 内核中落地：

1. **命令要能声明参数**：`CommandInfo.Arguments`（`CommandArgumentInfo`：Key、名称、单位、上下限、默认值）。内核按声明拒绝缺参数、未知参数、越界与非有限值，补全默认值，并把设定值写进确认文案与命令日志。
2. **设定命令的安全等级是输出动作**，不是写参数：实机下每次都要操作员确认，并受下游停用位置的联锁约束。

## 2. 共同规则

| 项 | 规则 |
|---|---|
| 分类 | `DeviceCategory.PowerAndLoad` |
| 通道 | 每个可以单独接线的端子是一路通道；单路设备也声明一组、数量 1 |
| 点位归属 | 多路设备的读数点位必须是**通道级**（`Group` = 通道组 Key，上报时填通道号）；单路设备可以用模块级 |
| 功率 | 设备没有功率读数时，用**同一次轮询**的电压 × 电流算出，不要跨两次轮询相乘 |
| 合理性 | 读数超出额定值的 -5% ~ +120% 视为数据损坏，返回 `Transient`，不上报 |
| 设备保护 / 报警 | 返回 `Failed(…, FailureKind.Device)`，原因里写明哪一路、哪一项保护，附原始状态字 |
| 安全等级 | 会改变输出 / 拉载的命令至少 `Output`；高压（>60 V DC）或单路 > 100 A 的设备用 `Hazardous` |
| 命令参数 | 一律用 `CommandArgumentInfo` 声明，范围取设备额定值；驱动按同一份声明再校验一次 |
| 不支持的命令 / 参数无效 | 第一步就 `Failed(…, Configuration)`，不发送任何字节 |
| 仿真设备 | 必须实现，命令后读数要随之变化，便于不接设备跑通测试流程 |

## 3. 程控电源

### 3.1 通道组

| Key | 名称 | 功能 | 数量 |
|---|---|---|---|
| `output` | 输出 | `PowerSupply` | 输出路数 |

### 3.2 点位

| Key | 名称 | 单位 | 必须 | 说明 |
|---|---|---|---|---|
| `voltage` | 输出电压 | V | 是 | |
| `current` | 输出电流 | A | 是 | |
| `power` | 输出功率 | W | 是 | 设备没有时用电压 × 电流 |
| `output` | 输出状态 | — | 是 | 1 = 输出已打开，0 = 关闭 |

### 3.3 命令

| Key | 名称 | 安全等级 | 参数 | 必须 |
|---|---|---|---|---|
| `output.on` | 打开输出 | `Output` | 无 | 是 |
| `output.off` | 关闭输出 | `Output` | 无 | 是 |
| `output.set` | 设定输出 | `Output` | `voltage`（V，必填）、`current`（A，限流，必填） | 推荐（首个实现时按本表） |

规则：

- 开关输出后**回读确认**设备状态（参考 `Chroma62000BSession` 的 `OutputExchange`），与期望不符返回 `Device`。
- `output.set` 在输出已打开时会立即改变输出，因此是 `Output` 而不是 `Parameter`。

## 4. 电子负载

### 4.1 通道组

| Key | 名称 | 功能 | 数量 |
|---|---|---|---|
| `load` | 负载 | `Load` | 负载通道数 |

### 4.2 点位（通道级，`Group = "load"`）

| Key | 名称 | 单位 | 必须 | 说明 |
|---|---|---|---|---|
| `voltage` | 电压 | V | 是 | 负载输入端电压 |
| `current` | 电流 | A | 是 | 负载吸收的电流 |
| `power` | 功率 | W | 是 | 设备没有时用电压 × 电流 |
| `input` | 带载状态 | — | 是 | 1 = 正在带载（输入开启），0 = 未带载 |

厂家特有的诊断量（原始状态字、逆变器状态等）可以另加点位，Key 不得与上表冲突。

### 4.3 命令（通道级，`Group = "load"`）

| Key | 名称 | 安全等级 | 参数 | 必须 |
|---|---|---|---|---|
| `load.cc` | 恒流带载 | `Output` | `current`（A，必填） | 是 |
| `load.cv` | 恒压带载 | `Output` | `voltage`（V，必填） | 设备支持时 |
| `load.cp` | 恒功率带载 | `Output` | `power`（W，必填） | 设备支持时 |
| `load.cr` | 恒阻带载 | `Output` | `resistance`（Ω，必填） | 设备支持时 |
| `load.off` | 卸载 | `Output` | 无 | 是 |

- 可选参数必须带默认值，如 `load.cc` 的 `start-delay`（启动延迟，s，默认 0）。
- 厂家特有的模式用另外的 Key 扩展，如 `load.cc-fast`（CC 快速）。
- 测试流程只使用本表的必须命令与 `current` / `voltage` 参数，就能驱动任何一家的电子负载。

### 4.4 必须实现的行为

1. **卸载在驱动层面永远可执行**：`load.off` 不带参数、不依赖任何设定，是电子负载的安全方向。（内核的停用位置联锁目前对卸载同样生效，见第 5 节第 1 项。）
2. **设定镜像**（协议只能一帧写全部通道时）：
   - 会话保存设备**已确认**的各路设定，命令只替换目标通道，其余各路按镜像原样重发；
   - 会话创建时镜像为"全部卸载"：第一条命令会把其他通道一并卸载，宁可多卸载，也不凭猜测给别的通道拉载；
   - 只有设备确认（应答正常）才更新镜像；超时或报错时不更新，下一条命令重新下发全部通道，使设备回到已知状态。
3. **参数双重校验**：内核按声明校验；驱动在编码前按同一份声明再校验一次（旧内核原样转交参数时也不会写出越界值）。
4. **功率由设备保护**：CC 设定 × 实际输入电压可能超过额定功率，驱动无法预知，依靠设备的超功率保护并上报为 `Device`。
5. **保护与报警**：任何一路的保护位、逆变器 / 电网故障都返回 `Device`；没有手册依据的状态（如空闲时是否报欠压）做成模块参数，默认报警。
6. **回读确认**：协议能读回设定时，带载 / 卸载后回读核对；不能读回的，在驱动对接说明里列为实机待确认项。

### 4.5 模块参数

| Key | 名称 | 类型 | 说明 |
|---|---|---|---|
| `von` | 拉载电压 Von | 数值，V | 输入电压高于 Von 才开始拉载；与被测产品有关，按现场配置。设备支持时必须提供 |

厂家特有参数（报文校验开关、报警策略等）另加，必须有保守的默认值。

### 4.6 测试流程如何下发

```csharp
// 产品位上功能为"负载"的那路接线：恒流 5 A
var plan = commands.Prepare(new DeviceCommandRequest(productId, ChannelKind.Load, purpose: null, "load.cc")
{
    Arguments = new Dictionary<string, double> { ["current"] = 5 },
});
// plan.Value.Describe() 含"参数：电流 5 A、启动延迟 0 s"；实机下需要操作员确认后再 ExecuteAsync
```

## 5. 内核与界面的现状和后续优化

本次已落地：

| 项 | 内容 |
|---|---|
| SDK 1.2 | `CommandArgumentInfo` 与 `CommandInfo.Arguments`；`DriverInfo.Validate` 校验参数声明。只加成员，1.0 / 1.1 驱动包不需要重新编译 |
| 内核 | `DeviceCommandService` 按声明校验参数、补默认值、冻结；确认文案与命令日志列出参数值；`DeviceCommandOption` 带参数声明 |
| 界面 | 接线面板暂不列出带必填参数的命令（点了只会被拒绝），卸载等无参数命令照常可用 |
| 驱动 | `gj.drivers` 包，`gj.da750-4-60a` 驱动、仿真设备与 63 个测试 |

仍需优化（按安全优先级排序）：

1. **安全停止钩子**（高）：现在总线安全跳闸、系统急停只锁存 SafeStop 并关闭通道，不向设备发任何报文，电子负载会**保持最后的设定继续拉载**，电源保持输出（DA750 逆变器状态里有"超时故障"位，可能是设备自带的通信看门狗，未经实机确认，不能依赖）。建议 SDK 增加可选能力，如 `ISafeStateProvider.BeginSafeStop()`（负载全部卸载、电源关闭输出），内核在急停 / 跳闸时先下发它再停止通信；同时让内核识别安全方向的命令（卸载、关闭输出），不受停用位置联锁阻挡。
2. **通道级报警**（中）：SDK 1 只能让整次轮询失败，一路保护会让 4 路读数全部看不到。建议 SDK 支持"读数照常上报 + 某几路报警"。
3. **接线面板参数输入**（中）：按 `DeviceCommandOption.Arguments` 生成输入框（名称、单位、范围），输入后进入同一个确认流程。完成后撤掉面板对带必填参数命令的过滤。
4. **多路设备的模块级命令**（低）：内核目前拒绝按位置下发多路设备的模块级命令（会影响其他位置），"全部卸载"只能在安全停止钩子里实现，不要作为普通命令开放。
5. **文档同步**：`Docs/驱动开发规范.docx` 与 `Devicelibrary/README.md` 同源，README 已更新到 SDK 1.2，docx 需要重新生成。

## 6. 电子负载驱动自检清单

- [ ] 通道组 `load`，功能 `Load`，数量等于负载通道数
- [ ] 点位 `voltage` / `current` / `power` / `input` 都是通道级，上报时填通道号
- [ ] 命令 `load.cc`、`load.off` 齐全，安全等级不低于 `Output`；参数用 `CommandArgumentInfo` 声明，范围取额定值
- [ ] 驱动对参数再校验一次；不支持的命令、越界参数不发送任何字节
- [ ] 一帧写全部通道的协议实现了设定镜像：初始全部卸载、确认后才提交
- [ ] 保护位、逆变器 / 电网故障返回 `Device`，原因写明通道与保护名称
- [ ] 读数有合理性检查；数值注释写明字节序、符号、倍率、单位
- [ ] 仿真设备：带载后读数变化，卸载后归零
- [ ] 有驱动对接说明（`Docs/` 下），列出协议依据、与旧实现的差异、实机待确认项与台架验证步骤
